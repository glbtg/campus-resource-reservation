# 简历写法参考

## 校园资源预约管理系统

**后端开发**　　　　　　　　　　　　　　　　**2025.xx - 2025.xx**

**项目简介：**  
基于 Spring Boot + MyBatis-Plus 的校园资源预约管理系统，面向学生和管理员提供资源查询、预约申请、预约取消、预约记录管理、资源类型维护、预约时段管理等功能。系统通过 MySQL 存储资源和预约数据，使用 Redis 缓存热点资源信息，并结合 Redisson 分布式锁、MySQL 事务和唯一索引解决同一资源同一时段的重复预约问题。

**技术栈：**  
Spring Boot / MyBatis-Plus / MySQL / Redis / Redisson / JWT / Swagger / Linux

**个人职责：**

- 负责学生登录注册、资源查询、时段查询、预约提交、预约取消、管理员资源维护等核心接口开发。
- 设计用户表、资源类型表、校园资源表、预约时段表、预约记录表等核心表结构，并针对资源时段查询、用户预约记录查询等场景建立组合索引。
- 使用 Redis 缓存资源详情和可预约时段列表，降低高频查询对 MySQL 的访问压力，并在预约、取消和资源修改后主动删除缓存保证最终一致。
- 针对同一时段的并发预约问题，使用 Redisson 按 `slotId` 加分布式锁，避免多个请求同时扣减余量。
- 使用 MySQL 事务保证时段余量扣减与预约记录写入的一致性，失败时统一回滚。
- 通过 `user_id + slot_id + active_flag` 唯一索引防止同一用户重复预约同一时段，作为并发控制的数据库兜底方案。
- 使用 Swagger 和 IDEA HTTP Client 编写接口测试流程，并在 Linux/Docker 环境中完成 MySQL、Redis 和后端服务部署。

**技术亮点：**

- Redisson 分布式锁解决并发预约冲突
- MySQL 事务保证预约流程一致性
- 唯一索引兜底防止重复预约
- Redis 缓存热点资源详情和时段列表
- 组合索引优化资源时段与预约记录查询

## 面试回答模板

面试官问“你这个项目里最有技术含量的地方是什么？”可以回答：

> 我觉得最核心的是预约并发控制。用户提交预约时，我会先根据时段 ID 获取 Redisson 分布式锁，让同一个时段的预约请求串行执行。拿到锁后，在事务里校验时段状态和剩余容量，再扣减时段容量并插入预约记录。如果过程中任何一步失败，事务会回滚。另外，我在预约记录表上加了 `user_id + slot_id + active_flag` 的唯一索引，防止同一用户重复预约同一时段。Redis 锁主要解决并发体验，唯一索引作为数据库层兜底。

面试官问“为什么取消预约后还能再次预约？”可以回答：

> 我没有直接用 `user_id + slot_id` 做唯一索引，因为这样取消后也不能再次预约。我加了一个 `active_flag` 字段，预约有效时是 1，取消或完成后置为 NULL。MySQL 唯一索引允许多个 NULL，所以能做到有效预约唯一，但历史取消记录可以保留。
